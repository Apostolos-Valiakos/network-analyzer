1. Overview & Deployment Topology

A full deployment involves three separate machines (or processes). Each can run on the same host for development, but in a production scenario they are typically separated as shown below.

Figure 1 – Deployment Topology
  ┌─────────────────────────┐     ┌─────────────────────────┐
  │   APPLICATION SERVER    │     │      SENSOR VM          │
  │                         │     │                         │
  │  ┌───────────────────┐  │     │  start_sensor.sh        │
  │  │  Flask API :5555  │◄─┼─────┼─ zeek_agent.py          │
  │  └─────────┬─────────┘  │     │  pcap_server.py :5005   │
  │            │ SQLAlchemy │     │  Zeek + dumpcap         │
  │  ┌─────────▼─────────┐  │     └─────────────────────────┘
  │  │  PostgreSQL 14    │  │
  │  │  + TimescaleDB    │  │     ┌─────────────────────────┐
  │  └───────────────────┘  │     │     USER BROWSER        │
  │                         │     │                         │
  │  ┌───────────────────┐  │     │  http://<host>:3000     │
  │  │  Nuxt SPA  :3000  │◄─┼─────┼─ Analyze / Cluster /   │
  │  └───────────────────┘  │     │  Monitor / Admin        │
  └─────────────────────────┘     └─────────────────────────┘

2.2 Install System Dependencies

Ubuntu / Debian

sudo apt update
sudo apt install -y python3.11 python3.11-venv python3-pip \
    wireshark-common tshark \
    postgresql postgresql-contrib

Install TimescaleDB

# Add TimescaleDB repository
sudo apt install -y gnupg postgresql-common apt-transport-https lsb-release wget
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh

# Install for PostgreSQL 14
sudo apt install -y timescaledb-2-postgresql-14

# Tune PostgreSQL for TimescaleDB
sudo timescaledb-tune --quiet --yes

# Restart PostgreSQL
sudo systemctl restart postgresql

2.3 Create the PostgreSQL Database

# Switch to the postgres superuser
sudo -u postgres psql

-- Inside psql:
CREATE USER netanalyzer WITH PASSWORD 'choose_a_strong_password';
CREATE DATABASE network_analyzer OWNER netanalyzer;
\c network_analyzer
CREATE EXTENSION IF NOT EXISTS timescaledb;
\q

2.4 Set Up the Python Environment

# From the project root
cd server

# Create an isolated virtual environment
python3.11 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# Install all Python dependencies
pip install --upgrade pip
pip install -r requirements.txt

# Flask-SocketIO is required but not in requirements.txt — install it now
pip install flask-socketio
Note: On some systems pyshark requires tshark to be in PATH. Verify with: tshark --version. If not found, add the Wireshark bin directory to your system PATH.

2.5 Configure the Environment File

Copy .env.example from the project root to .env and fill in every value. The backend will refuse to start if JWT_SECRET_KEY is absent. 

cp .env.example .env
nano .env   # or use any text editor
VariableRequiredDescription
DATABASE_URLYesPostgreSQL connection string, e.g. postgresql://netanalyzer:password@localhost:5432/network_analyzer
JWT_SECRET_KEYYesLong random string (min 32 chars). Generate with: python3 -c "import secrets; print(secrets.token_hex(32))"
INTERNAL_TOKENYesShared secret between Flask API and Sensor VM. Must match SECRET_TOKEN on the sensor.
ALLOWED_ORIGINSYesComma-separated list of frontend origins, e.g. http://localhost:3000,http://192.168.1.10:3000
VUE_APP_API_BASE_URLNoUsed by the frontend build; set here for convenience. e.g. http://192.168.1.10:5555

2.6 Initialise the Database Schema

# Still inside server/ with .venv activated
python - <<'EOF'
from app import app
from models import db
with app.app_context():
    db.create_all()
    print("Schema created successfully.")
EOF

2.7 Create the First Admin User

python - <<'EOF'
from app import app
from models import db, User
from werkzeug.security import generate_password_hash
with app.app_context():
    user = User(
        username="admin",
        password_hash=generate_password_hash("change_me_now"),
        role="admin"
    )
    db.session.add(user)
    db.session.commit()
    print("Admin user created.")
EOF
Warning: Change the admin password immediately after first login. The password above is a placeholder only.

2.8 Start the Backend

# From server/ with .venv activated
python app.py

# * Running on http://0.0.0.0:5555
# * Swagger UI available at http://0.0.0.0:5555/apidocs

npm run api   (calls python3 server/app.py)

3.2 Configure the Frontend Environment

The frontend reads VUE_APP_API_BASE_URL at build time to know where the Flask API lives. Set it in .env at the project root (same file as the backend): 

# .env  (project root)
VUE_APP_API_BASE_URL=http://192.168.1.10:5555
Important: If the Flask API is on a different machine from the browser, use the API server's LAN IP (or domain name) — not 127.0.0.1. The browser must be able to reach this address directly.

3.3 Install Node Dependencies

# Build the optimised bundle

3.6 Optional: Nginx Reverse Proxy

For production it is recommended to place Nginx in front of both the Nuxt server (port 3000) and the Flask API (port 5555) so that both are accessible on standard HTTP/HTTPS ports. 

# /etc/nginx/sites-available/network-analyzer
server {
    listen 80;
    server_name your.domain.com;

    # Frontend
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
    }

    # Flask API + WebSocket
    location /api/ {
        rewrite ^/api(/.*)$ $1 break;
        proxy_pass http://127.0.0.1:5555;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
    }
}

sudo ln -s /etc/nginx/sites-available/network-analyzer /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

4. Sensor VM Installation (Host Files)

The Sensor VM is a Linux machine physically connected to (or mirroring) the network you want to monitor. It runs three components:

  • Zeek IDS — parses live traffic and writes conn.log in JSON format.
  • dumpcap — captures raw packets into a rolling ring-buffer of PCAP files.
  • zeek_agent.py — tails conn.log and batches flow records to the Flask API every 2 seconds (or 50 records, whichever comes first).
  • pcap_server.py — lightweight Flask server on port 5005 that serves PCAP slices to the application server on demand.

4.1 System Requirements

ComponentMinimumNotes
OSUbuntu 22.04 LTS / Debian 12Must be Linux — shell scripts use bash
Python3.10+For zeek_agent.py and pcap_server.py
Zeek6.x (LTS)Installed to /opt/zeek/
Wireshark CLI3.xProvides dumpcap, mergecap, editcap
Nmap7.xRequired for on-demand network scans
NIC1 Gbps+Must be in promiscuous mode for passive capture

4.2 Install System Packages

sudo apt update
sudo apt install -y python3 python3-pip wireshark-common tshark nmap curl wget
Note: When prompted during Wireshark installation "Should non-superusers be able to capture packets?" — answer Yes if you want to run dumpcap without sudo. Otherwise the sensor scripts must be run as root.

4.3 Install Zeek

# Add the Zeek package repository (Ubuntu 22.04 example)
echo 'deb http://download.opensuse.org/repositories/security:/zeek/xUbuntu_22.04/ /' \
    | sudo tee /etc/apt/sources.list.d/security:zeek.list

curl -fsSL https://download.opensuse.org/repositories/security:zeek/xUbuntu_22.04/Release.key \
    | gpg --dearmor | sudo tee /etc/apt/trusted.gpg.d/security_zeek.gpg > /dev/null

sudo apt update
sudo apt install -y zeek

# Add Zeek to PATH
echo 'export PATH=$PATH:/opt/zeek/bin' >> ~/.bashrc
source ~/.bashrc

# Verify
zeek --version

4.4 Install Python Dependencies for Sensor Scripts

pip3 install requests flask

4.5 Copy Sensor Files to the VM

Copy the three files from the Host Files/ directory of the project to a working directory on the Sensor VM (e.g. ~/sensor/): 

# From the application server (using scp)
scp "Host Files/start_sensor.sh" \
    "Host Files/zeek_agent.py" \
    "Host Files/pcap_server.py" \
    user@sensor-vm-ip:~/sensor/

# On the Sensor VM — make the shell script executable
chmod +x ~/sensor/start_sensor.sh

4.6 Configure the Sensor

All sensor configuration is hardcoded at the top of each file — there is no .env file on the sensor machine. Open each file and replace the placeholder values before deploying.

zeek_agent.py — top of file

# ─── Configuration ────────────────────────────────────────────────────────────
ZEEK_LOG_PATH = "conn.log"
HOST_API_URL  = "http://<application-server-ip>:5555/v1/ingest/zeek"
SECRET_TOKEN  = "same_value_as_INTERNAL_TOKEN_in_backend_env"
# ──────────────────────────────────────────────────────────────────────────────

pcap_server.py — top of file

# ─── Configuration ────────────────────────────────────────────────────────────
SECRET_TOKEN = "same_value_as_INTERNAL_TOKEN_in_backend_env"
# ──────────────────────────────────────────────────────────────────────────────

start_sensor.sh — top of file

# ─── Configuration ────────────────────────────────────────────────────────────
HOST_IP="<sensor-vm-ip>"        # this machine's IP — excluded from capture
SENSOR_PORTS="5000 or port 5001 or port 5005"
# ──────────────────────────────────────────────────────────────────────────────
Important: SECRET_TOKEN in both Python files must be exactly the same string as INTERNAL_TOKEN in the Flask backend's .env. A mismatch will cause all Zeek flow ingestion to fail with HTTP 401.

4.7 Start the Sensor

cd ~/sensor

# Run the sensor on your chosen network interface
# Replace 'eth0' with the actual interface name (use 'ip link' to list interfaces)
./start_sensor.sh eth0

Successful output looks like: 

[*] Cleaning up old PCAP and log files...

 Starting Sensor Node on interface: eth0

[*] Starting dumpcap (Ring Buffer)...
[*] Starting Zeek...
[*] Starting PCAP Server (Port 5005)...
[*] Starting Zeek Agent...

------------------------------------------------

Sensor is active! Press [CTRL+C] to stop.

------------------------------------------------

Press Ctrl+C to stop all sensor processes cleanly.

Figure 2 – Sensor VM Internal Flow
  Network Interface (promiscuous mode)
           │
           ├──────────────────────────────────┐
           │                                  │
  ┌────────▼────────┐                ┌────────▼────────┐
  │   Zeek IDS      │                │   dumpcap       │
  │ -C -i eth0      │                │ ring buffer     │
  │ LogAscii JSON   │                │ 500 MB / file   │
  └────────┬────────┘                │ 3 files max     │
           │ conn.log (JSON lines)   └────────┬────────┘
           │                                  │ generated_pcaps/
  ┌────────▼────────┐                ┌────────▼────────┐
  │ zeek_agent.py   │                │ pcap_server.py  │
  │ tail + batch    │                │ Flask :5005     │
  │ 50 flows / 2 s  │                │ GET /get-pcap   │
  └────────┬────────┘                └────────┬────────┘
           │ POST /v1/ingest/zeek              │ on-demand slice
           │ X-Internal-Token                  │ (mergecap + editcap)
           ▼                                   ▼
     Flask API :5555              Flask API :5555
   (flow_statistics DB)         (snapshot download)

4.9 Finding Your Network Interface Name

ip link show
# or
ip a
# Look for an interface that is UP and connected, e.g. eth0, enp0s3, ens3
Tip: For passive monitoring without disrupting traffic, place the sensor on a network mirror port (SPAN) or use a network TAP. The -C flag passed to Zeek disables checksum verification, which is necessary when capturing from mirror ports.

5. Verifying the Full Stack

5.1 Backend Health Check

# From any machine on the network
curl -s http://<app-server-ip>:5555/apidocs | grep -c "swagger"
# Should return 1 (Swagger UI HTML is present)

5.2 Frontend Health Check

Open a browser and navigate to http://<app-server-ip>:3000. You should see the login page. Log in with the admin credentials created in Section 2.7.

5.3 Zeek Flow Ingestion Check

# On the application server — query the flow_statistics table
sudo -u postgres psql -d network_analyzer -c \
    "SELECT COUNT(*) FROM flow_statistics;"
# Row count should increase every few seconds while the sensor is running.

5.4 PCAP Server Check

# From the application server — request the latest PCAP from the sensor
curl -s -o /dev/null -w "%{http_code}" \
    -H "X-Internal-Token: <your-INTERNAL_TOKEN>" \
    http://<sensor-ip>:5005/get-pcap
# Should return 200

6. Running as System Services (systemd)

For production deployments, use systemd unit files so that the backend, frontend, and sensor restart automatically after a reboot.

6.1 Flask API Service

# /etc/systemd/system/netanalyzer-api.service
[Unit]
Description=Network Analyzer Flask API
After=network.target postgresql.service

[Service]
User=www-data
WorkingDirectory=/opt/network-analyzer/server
EnvironmentFile=/opt/network-analyzer/.env
ExecStart=/opt/network-analyzer/server/.venv/bin/python app.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

sudo systemctl daemon-reload
sudo systemctl enable --now netanalyzer-api
sudo systemctl status netanalyzer-api

6.2 Nuxt Frontend Service

# /etc/systemd/system/netanalyzer-frontend.service
[Unit]
Description=Network Analyzer Nuxt Frontend
After=network.target netanalyzer-api.service

[Service]
User=www-data
WorkingDirectory=/opt/network-analyzer
EnvironmentFile=/opt/network-analyzer/.env
ExecStart=/usr/bin/npm run start
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

sudo systemctl enable --now netanalyzer-frontend

6.3 Sensor Service

# /etc/systemd/system/netanalyzer-sensor.service
[Unit]
Description=Network Analyzer Sensor Node
After=network.target

[Service]
User=root
WorkingDirectory=/home/sensor-user/sensor
ExecStart=/bin/bash /home/sensor-user/sensor/start_sensor.sh eth0
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target

sudo systemctl enable --now netanalyzer-sensor
Note: Replace eth0 with your actual interface name. The sensor service runs as root because raw packet capture with dumpcap typically requires elevated privileges unless the system is explicitly configured otherwise.

7. Installation Troubleshooting

SymptomLikely CauseFix
RuntimeError: JWT_SECRET_KEY environment variable must be set .env not loaded or variable missing Confirm .env is in server/ and contains JWT_SECRET_KEY
psycopg2.OperationalError: could not connect to server PostgreSQL not running or wrong DATABASE_URL Run sudo systemctl start postgresql; verify pg_isready
ERROR: extension "timescaledb" does not exist TimescaleDB package not installed or wrong PostgreSQL version Re-run TimescaleDB install steps; confirm PG version with psql --version
ModuleNotFoundError: No module named 'pyshark' Virtual environment not activated or pip install not run Activate .venv and re-run pip install -r requirements.txt
tshark errors during PCAP analysis tshark not in PATH or version mismatch Run which tshark; add Wireshark bin to PATH if missing
npm install fails with EACCES npm global directory permissions issue Run as your user (not root); or fix npm prefix: npm config set prefix ~/.npm-global
Nuxt dev server can't reach Flask API (CORS error in browser) Frontend origin not in ALLOWED_ORIGINS Add http://localhost:3000 to ALLOWED_ORIGINS in .env
Zeek does not produce conn.log Zeek not installed at /opt/zeek/bin/zeek or interface wrong Run which zeek or /opt/zeek/bin/zeek --version; check interface name with ip a
Sensor: zeek_agent.py exits immediately with connection refused HOST_API_URL points to wrong host/port, or Flask API is down Verify Flask API is running; check HOST_API_URL at the top of zeek_agent.py
pcap_server.py returns 401 to the application server SECRET_TOKEN on sensor ≠ INTERNAL_TOKEN on backend Copy the exact same token string to the top of zeek_agent.py and pcap_server.py, and to INTERNAL_TOKEN in the backend .env
dumpcap: permission denied User not in wireshark group Run sudo usermod -aG wireshark $USER then log out and back in
mergecap or editcap not found Only tshark installed, not full Wireshark CLI tools Run sudo apt install -y wireshark-common
