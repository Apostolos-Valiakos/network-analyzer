1. Επισκόπηση & Τοπολογία Ανάπτυξης

3.6 Προαιρετικό: Nginx Reverse Proxy

Για παραγωγή συνιστάται η τοποθέτηση Nginx μπροστά από τον Nuxt (θύρα 3000) και τον Flask API (θύρα 5555) ώστε και οι δύο να είναι προσβάσιμοι σε στάνταρ HTTP/HTTPS θύρες. 

# /etc/nginx/sites-available/network-analyzer
server {
    listen 80;
    server_name your.domain.com;

    # Frontend
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
    }

    # Flask API + WebSocket
    location /api/ {
        rewrite ^/api(/.*)$ $1 break;
        proxy_pass http://127.0.0.1:5555;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
    }
}

sudo ln -s /etc/nginx/sites-available/network-analyzer /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

4. Εγκατάσταση VM Αισθητήρα (Host Files)

Το VM αισθητήρα είναι μια Linux μηχανή φυσικά συνδεδεμένη (ή καθρεφτισμένη) στο δίκτυο που θέλετε να παρακολουθείτε. Εκτελεί τέσσερα στοιχεία:

  • Zeek IDS — αναλύει ζωντανή κυκλοφορία και γράφει conn.log σε μορφή JSON.
  • dumpcap — καταγράφει ακατέργαστα πακέτα σε κυλιόμενο δακτύλιο αρχείων PCAP.
  • zeek_agent.py — παρακολουθεί το conn.log και αποστέλλει δέσμες εγγραφών ροών στο Flask API κάθε 2 δευτερόλεπτα (ή 50 εγγραφές, ό,τι συμβεί πρώτο).
  • pcap_server.py — μικρός Flask εξυπηρετητής στη θύρα 5005 που εξυπηρετεί τμήματα PCAP στον εξυπηρετητή εφαρμογής κατ' απαίτηση.

4.1 Απαιτήσεις Συστήματος

ΣυνιστώσαΕλάχιστοΣημειώσεις
ΛΣUbuntu 22.04 LTS / Debian 12Απαιτείται Linux — τα scripts χρησιμοποιούν bash
Python3.10+Για zeek_agent.py και pcap_server.py
Zeek6.x (LTS)Εγκατεστημένο στο /opt/zeek/
Wireshark CLI3.xΠαρέχει dumpcap, mergecap, editcap
Nmap7.xΓια σαρώσεις κατ' απαίτηση
NIC1 Gbps+Πρέπει να υποστηρίζει promiscuous mode

4.2 Εγκατάσταση Πακέτων Συστήματος

sudo apt update
sudo apt install -y python3 python3-pip wireshark-common tshark nmap curl wget
Σημείωση: Κατά την εγκατάσταση Wireshark, όταν εμφανιστεί η ερώτηση "Should non-superusers be able to capture packets?" — απαντήστε Yes αν θέλετε εκτέλεση dumpcap χωρίς sudo. Διαφορετικά τα scripts αισθητήρα πρέπει να εκτελούνται ως root.

4.3 Εγκατάσταση Zeek

# Προσθήκη αποθετηρίου πακέτου Zeek (παράδειγμα Ubuntu 22.04)
echo 'deb http://download.opensuse.org/repositories/security:/zeek/xUbuntu_22.04/ /' \
    | sudo tee /etc/apt/sources.list.d/security:zeek.list

curl -fsSL https://download.opensuse.org/repositories/security:zeek/xUbuntu_22.04/Release.key \
    | gpg --dearmor | sudo tee /etc/apt/trusted.gpg.d/security_zeek.gpg > /dev/null

sudo apt update
sudo apt install -y zeek

# Προσθήκη Zeek στο PATH
echo 'export PATH=$PATH:/opt/zeek/bin' >> ~/.bashrc
source ~/.bashrc

# Επαλήθευση
zeek --version

4.6 Διαμόρφωση Αισθητήρα

Όλη η διαμόρφωση του αισθητήρα βρίσκεται hardcoded στην αρχή κάθε αρχείου — δεν υπάρχει αρχείο .env στο VM αισθητήρα. Ανοίξτε κάθε αρχείο και αντικαταστήστε τις τιμές πριν από την ανάπτυξη.

zeek_agent.py — αρχή αρχείου

# ─── Configuration ────────────────────────────────────────────────────────────
ZEEK_LOG_PATH = "conn.log"
HOST_API_URL  = "http://<ip-εξυπηρετητή-εφαρμογής>:5555/v1/ingest/zeek"
SECRET_TOKEN  = "ίδια_τιμή_με_INTERNAL_TOKEN_στο_backend"
# ──────────────────────────────────────────────────────────────────────────────

pcap_server.py — αρχή αρχείου

# ─── Configuration ────────────────────────────────────────────────────────────
SECRET_TOKEN = "ίδια_τιμή_με_INTERNAL_TOKEN_στο_backend"
# ──────────────────────────────────────────────────────────────────────────────

start_sensor.sh — αρχή αρχείου

# ─── Configuration ────────────────────────────────────────────────────────────
HOST_IP="<ip-vm-αισθητήρα>"     # IP αυτής της μηχανής — εξαιρείται από την καταγραφή
SENSOR_PORTS="5000 or port 5001 or port 5005"
# ──────────────────────────────────────────────────────────────────────────────
Σημαντικό: Το SECRET_TOKEN και στα δύο αρχεία Python πρέπει να είναι ακριβώς η ίδια συμβολοσειρά με το INTERNAL_TOKEN στο .env του Flask backend. Αναντιστοιχία θα προκαλέσει αποτυχία όλης της εισαγωγής ροών Zeek με HTTP 401.

6. Εκτέλεση ως Υπηρεσίες Συστήματος (systemd)

Για αναπτύξεις παραγωγής, χρησιμοποιήστε αρχεία μονάδας systemd ώστε το backend, το frontend και ο αισθητήρας να επανεκκινούνται αυτόματα μετά από επανεκκίνηση.

6.1 Υπηρεσία Flask API

# /etc/systemd/system/netanalyzer-api.service
[Unit]
Description=Network Analyzer Flask API
After=network.target postgresql.service

[Service]
User=www-data
WorkingDirectory=/opt/network-analyzer/server
EnvironmentFile=/opt/network-analyzer/.env
ExecStart=/opt/network-analyzer/server/.venv/bin/python app.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

sudo systemctl daemon-reload
sudo systemctl enable --now netanalyzer-api
sudo systemctl status netanalyzer-api

6.2 Υπηρεσία Nuxt Frontend

# /etc/systemd/system/netanalyzer-frontend.service
[Unit]
Description=Network Analyzer Nuxt Frontend
After=network.target netanalyzer-api.service

[Service]
User=www-data
WorkingDirectory=/opt/network-analyzer
EnvironmentFile=/opt/network-analyzer/.env
ExecStart=/usr/bin/npm run start
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

sudo systemctl enable --now netanalyzer-frontend
