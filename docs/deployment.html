Deployment Guide

Install, run and update PENM

For whoever installs or maintains a PENM server: Docker on one Linux host, the capture sensor, updates and backups. Addresses are shown as placeholders such as <server-ip>.

1. What you are deploying

PENM has four parts. Three run as one Docker Compose stack (docker-compose.yml); the sensor is a separate container (docker-compose.sensor.yml) on the machine whose network interface it captures.

  Browser ──► frontend (nginx, :80) ──► backend (Flask/gunicorn, :5555) ──► db (PostgreSQL + TimescaleDB)
                                             ▲  │
              flows (POST /v1/ingest/zeek)   │  │ pcap slices, Nmap (:5005)
                                             │  ▼
                                   sensor (dumpcap, Zeek, pcap_server, publisher :5002)
  Real Time page ── WebSocket (:5002) ──► publisher.py on the sensor
ContainerWhat it doesPort
penm_frontendThe web application (Nuxt, served by nginx)80
penm_backendREST API, analysis, Swagger docs at /apidocs, live role snapshots5555
penm_dbPostgreSQL 14 with TimescaleDB; data in the db_data volume5432, local only
penm_sensorCaptures traffic, ships flows, serves pcaps and Nmap scans, streams packets to the Real Time page5005, 5002

Which setup to use:

SetupWhenWhere
App and sensor on one Linux hostUsual production setup: the host sees the traffic to monitorSections 3–6
App on one host, sensor on anotherThe traffic is only visible on a different machineSections 3–6, 6.3
Kubernetes testbedThe 5G testbed cluster (Open5GS, srsRAN, FlexRIC and PENM in one cluster)Section 10
Local developmentWorking on the codeDeveloper Guide

You never create the database or tables by hand. The database container creates network_analyzer on first start, and the backend applies its schema (Alembic migrations), enables TimescaleDB and creates the first admin account each time it starts, if needed.

2. Requirements

  • A Linux host (Ubuntu 22.04/24.04 or Debian), x86_64, with Docker Engine and the Compose plugin. Nothing else is installed on the host: Python, Node.js, nginx, PostgreSQL and tshark run inside the containers.
  • About 10 GB of disk for images and the database, plus space for capture files on the sensor host (see 6.2).
  • Ports 80 and 5555 reachable by the users' browsers; 5002 by browsers using the Real Time page; 5005 from the backend to the sensor.

3. Install Docker

sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker $USER && newgrp docker   # run docker without sudo
docker compose version                           # check

On Debian, replace ubuntu with debian in both URLs. If apt-get update fails with "cdrom … does not have a Release file", comment out the deb cdrom: line in /etc/apt/sources.list (a leftover from installing from an ISO).

4. Configure

Copy the project to the server (git clone, or copy the folder), then create .env next to docker-compose.yml. Compose reads it from the folder that holds the compose file, not from your current directory.

cd <project-folder>
cp .env.example .env
python3 -c "import secrets; print('JWT_SECRET_KEY=' + secrets.token_hex(32)); print('SECRET_TOKEN=' + secrets.token_hex(32))"
nano .env          # paste the two values and fill in the rest (table below)

.env holds secrets: never commit it or send it by e-mail. SECRET_TOKEN has no default. Without it the backend refuses all sensor traffic, and the sensor refuses all requests.

API_BASE_URL and WS_URL are compiled into the frontend, and nginx's security policy only lets the browser connect to those two addresses. After changing either, rebuild the frontend: docker compose build frontend && docker compose up -d frontend.

docker compose up -d --build        # first build: 5–10 minutes
docker compose logs -f backend      # wait for "Booting worker" and "TimescaleDB initialized successfully.", then Ctrl+C

Create the other user accounts in the application under Users (admins only). There is no self-registration.

6. The capture sensor

One container, penm_sensor, built from deploy/k8s/images/sensor/Dockerfile, runs everything the sensor needs:

ProcessPurposePort
dumpcapRing buffer of capture files (one per SENSOR_RING_SECONDS)—
Zeek + zeek_agent.pyFlow records, posted to the backend's /v1/ingest/zeek—
pcap_server.pyPcap slices and Nmap scans for the backend (token-protected)5005
publisher.pyLive packet stream for the Real Time page5002
dpi_agent.py (when SENSOR_DPI_ENABLED=true)Live DPI: two tshark processes decode the 5G protocols and post role evidence to the backend's /v1/ingest/dpi every minute—

It uses host networking, so it sees the host's real interface and opens 5005 and 5002 on the host itself. If a process stops, the container exits and Docker restarts it. Old capture files are deleted after SENSOR_RETENTION_MINUTES, and Zeek restarts daily so its log does not grow without limit. The sensor never sends a half-written capture: for the file being written it sends only the complete packets.

6.1 Build the image

docker build -f deploy/k8s/images/sensor/Dockerfile -t penm-sensor:latest .   # from the project root

Build on the server, or on another machine and copy it as in section 8 (docker save penm-sensor:latest | gzip > penm-sensor.tar.gz).

6.2 Settings

Put docker-compose.sensor.yml next to docker-compose.yml, so it shares .env (and SECRET_TOKEN) with the backend, and add:

# ── Sensor ──
SENSOR_INTERFACE=<interface>                          # list them with: ip -br addr
SENSOR_HOST_API_URL=http://127.0.0.1:5555/v1/ingest/zeek
SENSOR_URL=http://<sensor-ip>:5005
# optional
SENSOR_RETENTION_MINUTES=360                          # capture history (default 1440 = 24 h)
SENSOR_RING_SECONDS=3600                              # one capture file per hour
SENSOR_EXCLUDE_PORTS=5002 5005 5555                   # never captured (add 22 to drop SSH)
SENSOR_ENABLE_PUBLISHER=true                          # false: no Real Time stream

Capture files grow fast on a busy link: one hour at 100 Mbit/s is up to about 45 GB. Check df -h /var/lib/docker and size SENSOR_RETENTION_MINUTES to the free space.

6.3 Start and check

sudo ss -ltnp | grep -E ':(5005|5002)\b'                 # must print nothing (ports free)
docker compose -f docker-compose.sensor.yml up -d
docker logs penm_sensor | head                           # "[sensor] interface=<interface> filter: ..."
docker compose up -d --no-build backend                  # the backend reads SENSOR_URL at start

docker ps --format '{{.Names}}  {{.Status}}' | grep penm_sensor          # Up … (healthy)
docker logs penm_backend 2>&1 | grep "ingest/zeek" | tail -3           # flows arriving

Within a few minutes the Monitoring page shows statistics and Full Payload downloads a pcap. After the first snapshot interval, Run Analysis on Latest Slice works.

Sensor on another machine: install Docker there, copy the image and docker-compose.sensor.yml, and create a .env next to it with SECRET_TOKEN (the backend's value), SENSOR_INTERFACE and SENSOR_HOST_API_URL=http://<server-ip>:5555/v1/ingest/zeek. On the backend set SENSOR_URL=http://<sensor-ip>:5005, and build the frontend with WS_URL=ws://<sensor-ip>:5002.

Without Docker, Host Files/start_sensor.sh <interface> starts the same processes on a host that has tshark, Zeek and Python installed; it requires SECRET_TOKEN in the environment.

7. Access from other machines

  1. In .env: API_BASE_URL=http://<server-ip>:5555 and add http://<server-ip> to ALLOWED_ORIGINS.
  2. Rebuild the frontend: docker compose build frontend && docker compose up -d.
  3. If the firewall is on, open the ports: 
    sudo ufw allow 80/tcp && sudo ufw allow 5555/tcp && sudo ufw allow 5002/tcp
sudo ufw allow from 172.16.0.0/12 to any port 5005 proto tcp   # backend container → sensor on the same host

8. Updating a running server

Build the images on a workstation, copy them, and recreate only the backend and frontend. The database and its data are untouched. The backend upgrades the schema on its first start; upgrades only add what is missing, so keep a backup anyway.

8.1 On the server: find the project, back up, keep the old images

docker inspect penm_backend --format '{{index .Config.Labels "com.docker.compose.project"}}  {{index .Config.Labels "com.docker.compose.project.working_dir"}}'
docker inspect penm_frontend --format '{{range .Config.Env}}{{println .}}{{end}}' | grep -E 'API_BASE_URL|WS_URL'
docker exec penm_db pg_dump -U postgres -Fc network_analyzer > ~/penm_db_$(date +%F).dump
docker tag network-analyzer-backend:latest  network-analyzer-backend:old-$(date +%F)
docker tag network-analyzer-frontend:latest network-analyzer-frontend:old-$(date +%F)

The first command prints the Compose project name and <project-folder>. Compose names the images <project>-backend and <project>-frontend; the commands here assume the project is network-analyzer. The second prints the frontend's current addresses: reuse them below.

8.2 On the workstation: build and copy

In Git Bash or a Linux/macOS shell (not Windows cmd), from the project root:

docker build -t network-analyzer-backend:latest ./server
docker build -t network-analyzer-frontend:latest --build-arg API_BASE_URL=<api-base-url> --build-arg WS_URL=<ws-url> .
docker save network-analyzer-backend:latest network-analyzer-frontend:latest | gzip > penm-app.tar.gz
sha256sum penm-app.tar.gz
scp penm-app.tar.gz <user>@<server-ip>:~/

8.3 On the server: load and restart

sha256sum ~/penm-app.tar.gz                      # must match
gunzip -c ~/penm-app.tar.gz | docker load
cd <project-folder>                              # the folder holding docker-compose.yml
docker compose up -d --no-build backend frontend
docker logs -f penm_backend                      # "Starting gunicorn", migrations (if any), then Ctrl+C

--no-build makes Compose use the loaded images instead of building from the server's older source. Then reload the application in the browser with Ctrl+F5.

8.4 Roll back

docker tag network-analyzer-backend:old-<date>  network-analyzer-backend:latest
docker tag network-analyzer-frontend:old-<date> network-analyzer-frontend:latest
docker compose up -d --no-build backend frontend
# restore the data itself, if needed:
docker exec -i penm_db pg_restore -U postgres -d network_analyzer --clean --if-exists < ~/penm_db_<date>.dump

The sensor is updated the same way: load the new penm-sensor image, then docker compose -f docker-compose.sensor.yml up -d.

9. Daily operations and backups

docker compose ps                                  # status
docker compose logs -f backend                     # logs (frontend, db likewise)
docker compose restart backend
docker compose stop                                # stop, keep everything
docker compose down                                # remove containers, keep data volumes
docker compose -f docker-compose.sensor.yml logs -f
docker exec penm_db pg_dump -U postgres -Fc network_analyzer > ~/penm_db_$(date +%F).dump   # backup

docker compose down -v, docker volume prune and docker system prune --volumes delete the database volume. To free disk space, use docker builder prune and docker image prune, which keep volumes.

Data on the server: the database volume db_data; uploaded and generated captures, clustering output and results in the backend volumes; capture files in the sensor volumes. Back up the database regularly; the capture files are a rolling window and need no backup.

11. Troubleshooting

SymptomCause and fix
The app loads but every request fails, or the browser console shows "Content Security Policy" errorsThe frontend was built with a different API_BASE_URL than the address in use. Set it in .env and rebuild the frontend. Also check ALLOWED_ORIGINS.
Real Time page cannot connectWS_URL was built for another sensor address (nginx allows only that one), or port 5002 is closed, or the sensor runs with SENSOR_ENABLE_PUBLISHER=false.
Monitoring: "Sensor is unreachable" (503)SENSOR_URL wrong, sensor down, or firewall blocking 5005 from the Docker network (section 7). Restart the backend after changing SENSOR_URL.
No flows on the Monitoring page; backend log shows /v1/ingest/zeek … 401SECRET_TOKEN differs between backend and sensor, or is unset. It must be the same value in both .env files.
Run Analysis on Latest Slice says no snapshotThe backend has not fetched one yet (wait one SNAPSHOT_INTERVAL_SECONDS), the sensor is unreachable (backend log: "could not fetch a slice"), or SNAPSHOT_ENABLED=false.
/apidocs: "Missing Authorization Header"In Authorize, enter Bearer <token> and press Authorize. See the API Guide.
docker compose: "no configuration file provided"You are not in the folder that holds docker-compose.yml; find it with the first command of 8.1.
The update did not take effect (containers still "Up 2 weeks")docker compose up -d --no-build backend frontend was not run in the project folder, or the images were tagged under another project name.
Frontend image build fails in webpackBuild from the repository with its package-lock.json (the image uses npm ci); webpack 5 breaks Nuxt 2.
Uploaded or downloaded capture reported as "damaged"Captures copied while being written end in a partial record. PENM trims those on upload and when it reads a stored file; tools outside PENM may still complain about old copies.
