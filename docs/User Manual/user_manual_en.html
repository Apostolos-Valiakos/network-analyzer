1. Introduction

Network Analyzer is an open-source research platform developed at the University of Thessaly for the deep inspection and classification of 5G and 6G network traffic. It ingests raw PCAP captures or a live Zeek telemetry stream, applies unsupervised machine-learning clustering and rule-based role assessment, and delivers interactive dashboards for researchers, security analysts, and network engineers.

The platform addresses three primary research challenges:

  1. Traffic visibility — providing per-flow statistics, protocol distribution, and interactive network graphs from arbitrary PCAP files.
  2. Behavioural classification — automatically grouping IP endpoints by traffic behaviour using agglomerative clustering and assigning 5G/6G functional roles (UPF, AMF, gNB, UE, …) using a rule-based engine.
  3. Real-time situational awareness — streaming live Zeek connection logs into a TimescaleDB hypertable and surfacing anomalies via WebSocket-pushed alerts.

2. System Architecture

The system is structured in three tiers that communicate over REST and WebSocket (Socket.IO). An optional Host Sensor VM feeds live Zeek flow data and on-demand PCAP snapshots into the monitoring pipeline using a shared internal token.

3. Installation & Start-Up

3.1 Prerequisites

Before running the platform, ensure the following are installed on the server host:

  • Python 3.11+ — backend runtime
  • Node.js 18+ and npm — frontend build toolchain
  • PostgreSQL 14 with the TimescaleDB extension enabled
  • tshark / Wireshark — for PyShark-based PCAP decoding
  • Zeek IDS — Sensor VM only, for live telemetry
  • Nmap — Sensor VM only, for on-demand network scans

3.2 Environment Configuration

Copy .env.example to .env in the project root and fill in all required values. The backend reads this file at startup via python-dotenv. Never commit a populated .env to version control. 

# .env (example values — replace before use)
DATABASE_URL=postgresql://user:password@localhost:5432/network_analyzer
JWT_SECRET_KEY=change_me_to_a_long_random_string
INTERNAL_TOKEN=change_me_internal_token
ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
VUE_APP_API_BASE_URL=http://127.0.0.1:5555

3.3 Database Initialisation

# Create the database and enable TimescaleDB
psql -U postgres -c "CREATE DATABASE network_analyzer;"
psql -U postgres -d network_analyzer -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"

# Apply the ORM schema (run from the server/ directory)
cd server
python -c "from models import db; from app import app; app.app_context().push(); db.create_all()"

3.4 Starting the Backend

# From the project root
cd server
pip install -r requirements.txt
python app.py
# Server listens on http://0.0.0.0:5555

3.5 Starting the Frontend

# From the project root
npm install
npm run dev       # development — hot-reload on http://localhost:3000
npm run build     # production build
npm run start     # production server
Tip: Start the backend first, then the frontend. The Nuxt dev server proxies API calls to http://127.0.0.1:5555 as configured in nuxt.config.js.

4. Authentication

All pages except the public Swagger UI (/apidocs) require an authenticated session. The application uses JSON Web Tokens (JWT) with an 8-hour expiry. When the token expires the user is redirected to the login page automatically.

4.1 Logging In

  1. Navigate to http://<host>:3000/login.
  2. Enter your Username and Password and press Sign In or hit Enter.
  3. On success, the JWT is stored in the browser and you are redirected to the home dashboard.
  4. The header displays your username and a Logout button that clears the token immediately.

If you see an "Invalid credentials" error, verify your username and password. Contact your system administrator for account creation or password resets — there is no self-service registration.

5. PCAP Upload & Analysis

The Analyze page (/analyze) provides a one-step workflow: upload a .pcap file and receive a comprehensive analysis report — packet statistics, protocol distribution, conversation breakdown, interactive network graph, UE session extraction, and IP role assessment — all in a single API call.

5.1 Step-by-Step Workflow

  1. Click the file-input field labelled "Select .pcap file" and choose a valid PCAP file from your local filesystem.
  2. The file size is shown next to the filename for confirmation.
  3. Click Analyse. A progress indicator appears while the backend processes the capture.
  4. Once complete, the Total Packets summary card appears along with all analysis sections.
  5. Use Save Roles as JSON or Save Roles as CSV to export the role-assessment report for downstream tooling.
  6. Clear cached results removes the browser-stored previous results so a fresh upload starts from scratch.

5.2 Analysis Sections

SectionDescription
Total Packets Total count of captured packets in the file.
Protocol Distribution Pie/bar chart showing relative prevalence of TCP, UDP, GTP, SCTP, ICMP, and other protocols.
Conversation Statistics Per IP-pair traffic volume, packet count, and byte count.
Network Graph Interactive force-directed graph; nodes = IP addresses, edge weight = traffic volume.
IP Role Assessment Rule-based classification into 5G NF, O-RAN component, UE, external server, or unknown.
UE Sessions Extracted 4G/5G UE sessions — IMSI, GUTI, assigned IPv4, timestamps.
Note: Only .pcap files are accepted. PCAPNG files must be converted first using:
tshark -F pcap -r input.pcapng -w output.pcap

6. Agglomerative Clustering

The Clustering page (/clustering) exposes an advanced three-step workflow for applying hierarchical agglomerative clustering to a PCAP that has already been uploaded and processed by the backend.

Clustering groups IP endpoints by their traffic behaviour without requiring labelled training data (unsupervised learning). The platform uses graph modularity to automatically suggest the optimal number of clusters, so analysts do not need to guess.

6.1 Step 1 — Clustering

The stepper opens on the Clustering panel. The system has already computed a suggested cluster count based on the modularity score of the traffic graph. You may accept this suggestion or manually adjust the Number of Clusters slider. The dendrogram visualises how groups merge at each agglomerative linkage step; outlier IPs are flagged as anomalies.

6.2 Step 2 — Profiling

Select a cluster from the list to profile its member IPs. The profiling engine correlates port usage, connection patterns, and data volumes to assign each IP a probable 5G/6G functional role. Click Start Analysis with the desired cluster selected.

6.3 Step 3 — Results

The final results panel shows the complete role assessment for all clustered IPs. Download the PCAP for this session or export the role report as JSON or CSV.

7. Real-Time Streaming Analysis

The Real Time page (/realTime) enables live packet capture from a remote WebSocket source. A network tap or sniffer streams raw packet data in Base64-encoded chunks to the platform, which reassembles them server-side into a coherent PCAP file for immediate analysis.

7.1 Workflow

  1. Enter the WebSocket URL of the remote capture agent (e.g. ws://192.168.1.10:8080).
  2. Click Connect. The status indicator turns green and shows "Connected".
  3. In the Capture Controls panel:
    • Click Get Interfaces to list available network interfaces on the remote agent.
    • Select an interface from the dropdown.
    • Click Start Capture to begin recording.
  4. When sufficient data is collected, click Generate PCAP (active only while capturing). The backend finalises the file and a download link appears.
  5. Optionally send the assembled PCAP directly into the analysis pipeline.
Warning: The WebSocket source must be reachable from the browser. Firewall rules and NAT may need to be adjusted for cross-network deployments.

8. Continuous Monitoring

The Continuous Monitoring dashboard (/continuous_monitoring) provides a live view of network flows stored in the TimescaleDB hypertable (flow_statistics). Data arrives from the Host Sensor VM via the Zeek agent and the POST /v1/ingest/zeek endpoint.

8.1 Timeframe Selection

Choose a start and end datetime to query historical flows, or enable Live Mode to continuously refresh data at a fixed interval. Click Apply to fetch.

8.2 Flow Statistics Table

A sortable, filterable table shows all recorded connections: source IP, destination IP, source/destination ports, protocol, bytes sent/received, packet count, and timestamp. Click any column header to sort ascending/descending.

8.3 Anomaly Alerts

The backend evaluates each ingested batch of flows and pushes WebSocket alerts to all connected clients when it detects:

  • Massive data transfers (> 5 MB in a single flow)
  • Packet floods (> 5 000 packets in a single flow)
  • Rejected connections (TCP RST / ICMP unreachable)

Alerts appear as coloured snackbar notifications in the browser and are also logged server-side.

8.4 Nmap Scan Integration

Click Trigger Nmap Scan to instruct the Sensor VM to run an on-demand Nmap scan of the monitored subnet. Results are returned as a structured JSON object and displayed in the dashboard.

8.5 Export

Use the Download CSV / JSON buttons to export the currently displayed flow window for offline analysis.

9. API Reference

An interactive Swagger UI is served by the Flask backend at http://<host>:5555/apidocs. It documents every endpoint with parameters, request bodies, response schemas, and authentication requirements. No login is required to browse; endpoints that require a JWT token are marked with a lock icon. Use the Authorize button to supply your token for live interactive testing.

Flask-Limiter enforces per-IP rate limits to protect the server from abuse. Exceeding the limit returns HTTP 429 Too Many Requests. Consult the administrator for current thresholds.

10. Administration

The Admin panel (/admin) is accessible only to users with the admin role.

10.1 User Management

  • Create new user accounts by supplying a username, password, and role.
  • Deactivate or delete existing accounts.
  • Passwords are stored as bcrypt hashes — never in plain text.

10.2 System Overview

  • View all uploaded PCAP files, their analysis status, and timestamps.
  • View stored role snapshots and cluster results.
  • Purge old files or database records for storage management.
Security Note: The X-Internal-Token used by the Sensor VM must be kept secret and rotated regularly. Store it only in .env — never hardcode it in source code or commit it to version control.

11. Troubleshooting

SymptomLikely CauseFix
Login returns "Invalid credentials" Wrong username/password or account disabled Verify credentials; ask admin to reset or re-enable account
Upload fails with 413 PCAP exceeds server max upload size Increase MAX_CONTENT_LENGTH in app.py or split the PCAP
Analysis hangs indefinitely tshark not installed or not in PATH Install Wireshark/tshark; verify with tshark --version
Database connection error at startup DATABASE_URL not set or PostgreSQL not running Check .env; verify with pg_isready
TimescaleDB extension missing Extension not enabled in the database Run CREATE EXTENSION IF NOT EXISTS timescaledb; as superuser
WebSocket connection refused (Real Time page) Remote agent not running or firewall blocking Start the remote agent; open the WebSocket port in the firewall
Zeek ingest returns 401 Incorrect or missing X-Internal-Token Ensure Sensor VM .env matches server INTERNAL_TOKEN
Rate limit 429 on API Too many requests from client IP Reduce request frequency or ask admin to raise the limit
Frontend shows blank page after login CORS mismatch — origin not in ALLOWED_ORIGINS Add the frontend URL to ALLOWED_ORIGINS in .env
Clustering page shows no dendrogram PCAP has too few unique IPs (< 2) Use a PCAP with more varied traffic for meaningful clustering

12. Glossary

TermDefinition
PCAPPacket CAPture — binary file format for network traffic recordings.
JWTJSON Web Token — compact, signed token used for authentication.
5G NF5G Network Function — logical component of the 5G Core (e.g. AMF, UPF, SMF).
UEUser Equipment — mobile device connected to the network (phone, tablet, IoT).
gNBNext-Generation NodeB — 5G base station.
GTPGPRS Tunnelling Protocol — encapsulation protocol used in 4G/5G user plane.
ZeekNetwork analysis framework that generates structured connection logs from live traffic.
TimescaleDBPostgreSQL extension optimised for time-series data; adds hypertables and time-bucketing.
Agglomerative ClusteringBottom-up hierarchical clustering that merges the two most similar clusters at each step.
ModularityGraph-theory metric that measures the quality of a community partition.
AnomalyIP address or flow that deviates significantly from normal behaviour.
O-RANOpen Radio Access Network — open-interface radio access architecture for 5G/6G.
IMSIInternational Mobile Subscriber Identity — unique 15-digit identifier for a SIM.
GUTIGlobally Unique Temporary Identifier — privacy-preserving temporary UE identifier.
HypertableTimescaleDB table automatically partitioned by time for high-throughput time-series writes.
NmapNetwork Mapper — open-source tool for network discovery and security auditing.
