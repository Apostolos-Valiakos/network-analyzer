Developer Guide

Working on the PENM code

For developers changing PENM: layout, local setup, how the parts fit, conventions, tests and releases. CLAUDE.md in the repository root is the condensed version of the same rules.

2. Run it locally

Backend

Needs Python 3.10+, tshark on PATH (or TSHARK_PATH; on Windows the Wireshark install is found automatically) and PostgreSQL, preferably with TimescaleDB.

cd server
python -m venv .venv && source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# server/.env: JWT_SECRET_KEY, DATABASE_URL=postgresql://postgres:<pw>@localhost:5432/network_analyzer,
# SECRET_TOKEN, ADMIN_USERNAME/ADMIN_PASSWORD, ALLOWED_ORIGINS=http://localhost:3000,
# optionally SENSOR_URL and SNAPSHOT_ENABLED=false when no sensor is running
python app.py                 # http://127.0.0.1:5555, applies migrations; FLASK_DEBUG=1 for the debugger (never on an exposed host)

Frontend

npm ci                                         # exactly the committed package-lock.json
API_BASE_URL=http://127.0.0.1:5555 WS_URL=ws://127.0.0.1:5002 npm run dev          # http://localhost:3000
NODE_OPTIONS=--openssl-legacy-provider npm run generate                         # production build into dist/ (Node 17+)

API_BASE_URL and WS_URL are read at build time (nuxt.config.js); a root .env sets them too. A build made with someone else's .env points at their server.

3. Backend architecture

  • App factory. create_app(init_database=True) builds the app with no import side effects. On start, db_setup.init_database applies migrations, enables TimescaleDB (the flow_statistics hypertable) and seeds the first admin, under a Postgres advisory lock.
  • Production: gunicorn with one worker and 100 threads. One worker on purpose: Socket.IO clients, the rate limiter and the snapshot scheduler live in process memory.
  • One tshark pass per capture (packet_table.py): one tshark -T fields run extracts the union of all modules' fields into <pcap>.packets.tsv. Its header holds file size, modification time and field list, so a changed capture or field list re-extracts. Roles, privacy records, the traffic graph, clustering and UE extraction all read it. There is no other packet library in the backend.
  • Role engine (role_engine.py): direction-aware evidence (who listens on NGAP 38412 or E2AP 36421/36422, PFCP message direction, which side serves an SBI path), identities a node states about itself (NG Setup RAN/AMF names, E2 Setup node ID, PFCP Node ID and CP/UP Function Features, and NFProfiles in NRF signalling, whose nfType and ipv4Addresses name the NF even when requests come from another address or through the SCP), then a rule table gives one role per IP with confidence, reasoning and runner-ups. Results are cached per capture in ip_roles with the engine version; partial results are not cached.
  • Live DPI (Host Files/dpi_agent.py, live_roles.py): two live tshark processes at the sensor (control plane whole, GTP-U cut to 128 bytes) are parsed with role_evidence; every window (60 s) the agent posts the stage-1 evidence to /v1/ingest/dpi, re-sending windows the backend did not accept. The backend stores the window, keeps self-declared identities for 24 h, merges the last 15 minutes and writes a RoleSnapshot with source='dpi'. It runs alongside the pcap snapshots; /v1/network/roles/latest serves DPI while it is fresh.
  • Kubernetes identity (Host Files/hubble_agent.py, k8s_identity.py, role_fusion.py): the sensor runs hubble observe --follow against Hubble Relay and posts pod and Service sightings and per-minute flows to /v1/ingest/hubble (PENM's own pods left out). Where Hubble Relay cannot be reached, k8s_api_agent.py lists the pods and Services of K8S_NAMESPACES with the pod's ServiceAccount (read-only Roles per namespace, deploy/k8s/20-penm/sensor-rbac.yaml) and posts the same sightings with source: k8s-api, without flows. The backend keeps them as time spans per IP, so an IP reused after a restart maps to the right pod at each time. When role results are read (latest roles, /run_pipeline, /v1/analyze_live), role_fusion adds a k8s object from the hint table k8s_role_hints.json: an agreeing pod raises confidence by 0.10, a disagreeing one sets k8s_mismatch, an Unidentified IP gets suggested_role. With no Hubble data stored, results are left exactly as they were. evaluate_roles.py scores the stored snapshots against the pods (precision/recall per role, re-identification time after a pod restart).
  • Role pipeline (Preprocess.py): runs the role engine in a child process, so a hung tshark can be killed after 600 s, and writes the role summary served by /save_roles.
  • UE extraction (ueAnalysis.py): IMSI (also from null-scheme SUCI), 5G-TMSI, PDU session, and the UE address from the PDU Session Establishment Accept, linked to the IMSI through the HTTP/2 stream's /ue-contexts/imsi-… URL or the RAN UE NGAP ID.
  • Monitoring (blueprints/monitoring.py): Zeek flows into flow_statistics (naive UTC), statistics and export, pcap endpoints proxying the sensor's /get-pcap, and Socket.IO events.
  • Snapshot scheduler (snapshot_scheduler.py): a thread started from wsgi.py fetches the sensor's latest SNAPSHOT_INTERVAL_SECONDS, stores role-engine results as RoleSnapshot rows (pruned after SNAPSHOT_RETENTION_HOURS) and keeps results/latest_snapshot.pcap for /v1/analyze_live.
  • Server-side capture (connectToWebsocket.py): each /start-analysis-from-websocket request runs its own CaptureRun, saving and analysing in-process.
  • WP5 notices (wp5_notices.py): PENM's own alerts as Zeek Notice::Info JSON lines in WP5_NOTICE_LOG, forwarded to the XTRUST-6G alert system.
  • Auth: flask-jwt-extended, 8-hour tokens, admin checks in access.py. Sensor traffic uses X-Internal-Token = SECRET_TOKEN, checked with settings.token_matches (constant time, never true when unset).

4. Frontend

  • Static SPA (ssr: false), built with nuxt generate and served by nginx. nginx's Content Security Policy is generated at container start from API_BASE_URL and WS_URL.
  • Call the backend through plugins/api.js: this.$api.json(path, options, fallbackMessage) for JSON (shows the backend's error, else the fallback); $apiFetch only for downloads and where the status code matters. Both add the token and log out on 401.
  • Large pages are split into components: components/realtime/, components/history/, components/monitoring/, components/stepper/; pure helpers in utils/.
  • Use Vuetify 2 props and classes (outlined, dense, large, depressed, <v-icon left>, primary--text). Vuetify 3 forms (variant=, density=, size= on buttons) silently do nothing.
  • Jest compiles templates without optional chaining: write a && a.b instead of a?.b in templates.

5. Sensor

pcap_server.py picks the ring files continuous_capture_*.pcap that overlap a requested window, merges and cuts them with mergecap/editcap, and serves Nmap scans. For the file dumpcap is still writing it sends, or merges, only the complete records (pcap_repair.complete_length), and never modifies that file. The sensor image (deploy/k8s/images/sensor/) copies server/pcap_repair.py and server/role_evidence.py (the role engine's evidence collector, kept free of Flask and database imports for that reason); it has its own Dockerfile.dockerignore because the root one excludes server/.

6. Conventions

  • Swagger: every route has a server/docs/<name>.yml. Protected routes need security: [{Bearer: []}], or Swagger UI will not send the token. A test enforces this.
  • Partial failures: never swallow an exception. Log it with logger.exception; if the rest of the request still succeeds, add a readable message to a warnings list in the response (only when non-empty). The frontend shows it with components/WarningsAlert.vue. Bad parameters are 400, server errors 500.
  • Incomplete captures: stored captures are trimmed with pcap_repair.trim_incomplete_tail (on upload, Real Time save, scheduler download, and when first loaded).
  • Time: stored datetimes are naive UTC; the API uses Unix seconds.
  • Secrets: never commit .env, tokens, r13/secrets/ or Open5GS home-network keys. SECRET_TOKEN has no default anywhere.
  • Commits: topic commits on a branch, merged into main when the tests pass. There is no CI: run the tests yourself.

7. Tests

pip install -r server/requirements.txt -r tests/requirements.txt
pytest                                   # backend (from the repository root)
pytest -m "not integration"              # without tests that need real tshark
npx jest --config tests/frontend/jest.config.js
  • Snapshot tests (tests/backend/snapshots/*.json) pin current output: analysis results for two fixture captures, every route's response, the route table, the Swagger spec and CORS. After an intended change, re-record with pytest --update-snapshots and review the diff.
  • Snapshots record the tshark version. The main file is from the dev machine (tshark 4.6); the production image's tshark 4.4 is recorded as a mark (same output) or a <name>.tshark-4.4.json file. Re-record locally first, then in the image: 
    docker run --rm -v "<repo>:/repo" -w /repo --entrypoint sh network-analyzer-backend:latest \
  -c 'pip install -q -r tests/requirements.txt && python -m pytest --update-snapshots'
  • Patch where a name is used (blueprints.<area>.X). conftest.py sends WP5 notices to a temporary file, disables rate limits, and stubs snapshot_scheduler (its own tests load the real file).
  • PENM_TEST_POSTGRES_URL also runs the PostgreSQL-only migration tests against a throwaway database whose name contains "test".
  • Each pytest run uses its own SQLite file in a temporary folder (deleted at exit), so two runs at once (terminal and IDE) do not interfere.
  • Mutation testing (optional, to check that tests catch changes): StrykerJS for the frontend, npx stryker run (scope in stryker.config.json, report in reports/mutation/). mutmut needs Linux, so it runs in the backend image: 
    docker run --rm -v "<repo>:/repo:ro" --entrypoint sh network-analyzer-backend:latest \
  /repo/tests/mutation/mutmut_docker.sh
    Edit the file and test lists at the top of the script to change its scope.

8. Database changes

cd server
flask --app wsgi db migrate -m "describe the change"   # after editing models.py

Review the new file in migrations/versions/ and commit it; the next start applies it. test_models_match_the_migrations fails if a model changes without a migration.

9. Building and shipping

docker build -t network-analyzer-backend:latest ./server
docker build -t network-analyzer-frontend:latest --build-arg API_BASE_URL=<api-base-url> --build-arg WS_URL=<ws-url> .
docker build -f deploy/k8s/images/sensor/Dockerfile -t penm-sensor:latest .

Shipping to a server and rolling back: Deployment Guide, section 8. The frontend image installs with npm ci from the committed package-lock.json, which pins webpack 4 (webpack 5 breaks Nuxt 2). Change dependencies with npm install and commit the lockfile.
